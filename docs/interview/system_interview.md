# 系统问答

状态：概念性复核；本仓库没有 CPU 微架构、磁盘或操作系统调度实验。与 Go 程序可观察行为有关的入口见[编译笔记](../base/go_compile.md)、[GC 笔记](../base/go_gc.md)及[pprof 专题](../advanced/go_pprof.md)。

**CPU 读取数据经过哪些层级？** 寄存器、不同级别的缓存、主内存以及持久存储处于不同延迟和容量层次。处理器并非“只负责运算、不负责存储”：寄存器和缓存本身也保存状态。是否命中缓存、预取、乱序执行与具体 CPU 架构有关，不能用固定的一条访问顺序描述每次读取。

**寄存器和缓存有什么区别？** 寄存器由指令显式使用，缓存通常按内存地址及缓存层级管理数据。将寄存器称为“零级缓存”只是类比，不能据此推导相同的寻址、替换或一致性机制。

**Go 程序如何定位 CPU 或内存瓶颈？** 先用有代表性的负载和指标确认现象，再做基准测试、CPU profile、内存 profile 或执行跟踪；GC 指标仅能解释其中一部分。命令与适用边界见[测试专题](../advanced/go_testing.md)、[pprof 专题](../advanced/go_pprof.md)和[GC 指南](../base/go_gc.md)。这些工具报告具体运行环境的观察值，不保证跨机器重现相同结果。

本页没有新增自动测试；需要解释硬件层次或系统调用时，应注明 CPU、操作系统与测量工具版本。
