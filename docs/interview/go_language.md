# Go 语言问答

状态：按仓库 Go 1.25.5 复核语言规则；运行时实现只保留版本明确的说明。可从[基础索引](../base/README.md)、[反射专题](../advanced/go_reflect.md)和[测试专题](../advanced/go_testing.md)进入示例。下列答案以 [Go 语言规范](https://go.dev/ref/spec)为语义依据。

## 语法、返回与内存

**`new` 与 `make` 有什么区别？** `new(T)` 返回指向 `T` 零值的 `*T`；`make` 只初始化 slice、map、channel 并返回对应类型的值。两者都不能推出“必定分配在堆上”；见[编译与逃逸](../base/go_compile.md)。

**`defer` 与返回值顺序？** 返回表达式先求值，延迟调用按后进先出执行，然后函数返回。延迟函数可以修改具名返回值。发生 panic 时也会执行已注册的 defer；`os.Exit` 不会。用[错误处理笔记](../base/go_error.md)中的资源清理方式复习。

**闭包与循环变量？** 闭包捕获变量。Go 1.22 起，采用新语义的 `for` 循环变量在每次迭代中独立；旧版“一定要复制循环变量”不是 Go 1.25 的通用规则。见[语言总览](../base/go_manual.md)。

**怎么查看汇编？** `go build -gcflags=-S ./internal/godemo` 可输出本机编译器生成的汇编；诊断受版本、架构和优化影响，不能当作语言规范。逃逸信息见[编译笔记](../base/go_compile.md)。

## 数组、切片与 map

**数组和切片的区别？** 数组长度是类型的一部分，数组赋值复制元素；切片是指向底层数组片段的描述值。`nil` 切片长度和容量都是 0，可以 `append`，但不能索引 `s[0]`；非 nil 空切片也不能索引 `s[0]`。`append` 可能复用底层数组，也可能分配新数组，调用者要接收返回的切片。扩容倍率是实现细节，不承诺固定值。

**切片传参能否修改调用方？** 传递的是切片值的副本，共享底层数组的元素可被修改；对形参重新 `append` 后的长度变化不会自动写回调用方的切片头。若新数组被分配，后续元素修改也不再共享。需要同步长度时返回新切片。

**map 查询、遍历与删除？** `v, ok := m[k]` 用 `ok` 区分缺键与零值。遍历顺序未定义；在同一 goroutine 的遍历过程中删除尚未访问的键，该键不会再被产生；插入键是否被遍历不确定。并发读写同一普通 map 需要外部同步，参见[并发控制实践](../base/go_concurrency_practice.md)。

**map 的键、比较和取地址？** 键类型必须可比较，浮点数可以作键，但 NaN 不等于自身，作为键通常不合适。map 元素不可直接取地址。map 之间不能用 `==` 比较，除与 `nil` 比较外；要按内容比较可用 `maps.Equal` 或明确业务规则，复杂值参见[反射专题](../advanced/go_reflect.md)。

**`hmap`、桶链表与固定装载因子仍适用吗？** 不应把旧笔记里的结构体、8 槽桶和溢出链表当作当前 Go 的实现。Go 1.24 引入基于 Swiss Table 的新 map 实现；这不改变上述语言语义。实现演变见 [Go 官方文章](https://go.dev/blog/swisstable)。需要诊断当前版本时应查看当前工具链源码并注明版本。

## 接口、方法与反射

**值接收者和指针接收者如何影响接口实现？** `T` 的方法集包含值接收者方法；`*T` 的方法集还包含指针接收者方法。可寻址值有时可以直接调用指针接收者方法，是调用语法上的简写，不代表 `T` 实现了要求该方法的接口。接口中装入类型化 nil 指针时，接口本身通常不等于 nil。

**类型转换和类型断言有什么区别？** `T(x)` 按转换规则转换表达式；`v.(T)` 对接口的动态类型作断言，使用 `value, ok := v.(T)` 可避免断言失败的 panic。接口值的静态类型不会在运行时变成“动态类型”；见[反射专题](../advanced/go_reflect.md)。

**`unsafe` 能否当作通用指针转换？** 不能。`unsafe.Pointer` 的合法使用依赖具体规则、对象生命周期和对齐条件；不能借它绕过 map 元素不可取地址或并发同步要求。这里没有对应安全演示，需查 [unsafe 包文档](https://pkg.go.dev/unsafe)再针对具体代码审查。
