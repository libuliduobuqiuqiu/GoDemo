# 知识收纳与写作约定

## 放在哪个目录

- `base/`：Go 语言本身、标准库、并发、编译与运行时。
- `advanced/`：测试、调试、性能、数据库、RPC 等工程实践。
- `framework/`：特定框架的概念、项目结构和使用示例。
- `interview/`：问题与复盘提纲；已有专题的答案优先链接专题，不复制一份。

每个主题尽量只有一篇主笔记。文章名使用明确的主题词；新增文章后，在所属目录的 `README.md` 登记标题、状态和代码入口。知识库首页只保留阅读路径和目录入口。

## 一篇可复用的笔记应包含什么

1. **要解决的问题**：一句话说明场景与适用范围。
2. **核心结论**：先写可直接使用的规则，再写原因。
3. **最小示例**：链接仓库中可运行的代码或测试；若代码需要环境，给出准备条件。
4. **边界与易错点**：说明哪些条件会改变结论，以及常见失败方式。
5. **验证方式**：写精确命令和观察点；默认测试不能依赖私有配置或外部服务。

建议在文章开头标状态：`已整理并验证`、`局部校正，待全面复核` 或 `原始笔记`。只有核对过代码和运行结果后才标为“已整理并验证”。版本相关结论注明使用的 Go 版本，避免把实现细节当成永久语义。
